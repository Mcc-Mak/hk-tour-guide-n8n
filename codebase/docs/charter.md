# 專案章程

本專案章程（Project Charter）為「香港建築物導賞手冊自動化流水線」的正式授權文件，界定專案的願景、使命、範圍、利害關係人、成功準則與約束條件。所有後續需求、設計與實作文件均以本章程為最高指導原則。

## 願景

成為香港建築文化資產數位保存與公眾教育的權威知識庫，以自動化、可追溯、高可信度的方式，系統性地為香港每一座具歷史與文化價值的建築物產出專業級導賞手冊，讓本地市民、旅客、學生與研究員皆能便捷地理解香港建築的歷史脈絡與文化意義。

本專案願景的核心信念為：建築是城市記憶的載體，而可信的歷史敘事需建立在嚴格的事實查核之上。因此本專案不僅追求產出數量，更以「硬關卡（Hard Gate）」真實性審查機制確保每一段歷史陳述皆附可驗證來源，拒絕未經證實的推測性內容進入知識庫。

## 使命

以 CrewAI 多代理框架執行歷史檔案研究與可信度評估，透過 n8n 工作流引擎編排每座建築物的原子化迭代迴圈，並以 mdBook 編譯及發佈靜態文檔網站，全流程由 GitHub Actions CI/CD 流水線統一管控分支推進、品質掃描與自動部署。

本專案採兩階段架構：第一階段為提示詞工作流，由 CrewAI 產出專案鷹架（n8n 工作流 JSON、CrewAI 設定與完整文檔）；第二階段為 n8n 工作流，於鷹架成熟後啟動，負責編排每座建築物的迭代迴圈。兩階段皆受 GitHub 分支管線管控，確保品質閘門與可追溯性。

## 範圍

### 包含範圍

- 建立涵蓋香港市區、新界及法定古蹟三大類別的建築物清單（建築矩陣），作為流水線的輸入來源。
- 設計並實作 CrewAI 多代理系統，包含歷史檔案研究員、可信性評估員、導賞手冊撰寫員與專案經理四個代理。
- 以硬關卡標準審查每座建築物的歷史研究，確保所有事實陳述附可驗證來源；不通過時最多嘗試五次（1 次初試 + 4 次重試），仍未通過則執行跳過策略。
- 設計 n8n 自架 Docker 工作流，以 Webhook 觸發、原子化迭代處理每座建築物，單座失敗不中斷整體迴圈。
- 編譯 mdBook 靜態文檔網站並透過 GitHub Actions 自動部署。
- 建立完整文檔集（章程、需求、設計、架構決策、API、資料結構、工程記錄、配置、部署、設定、追溯矩陣、變更管理）。

### 不包含範圍

- 即時互動式導覽 App 或行動應用程式開發。
- 建築物現場實地測繪或三維模型製作。
- 付費雲端服務（如 n8n Cloud）的採購與整合；本專案僅使用自架免費 Community Edition。
- 非香港地區的建築物研究。
- 歷史人物傳記或非建築類文化資產的撰寫。

## 成功準則

1. **內容可信度** — 每份導賞手冊均通過硬關卡審查，所有事實陳述附可驗證來源，不接受無來源推測。
2. **覆蓋範圍** — 成功處理建築矩陣中具歷史價值的建築物，未通過硬關卡者記錄 Exception Log 並跳過，不污染知識庫。
3. **流程自動化** — n8n 工作流可由 Webhook 觸發，自動完成研究、審查、產出、版本控制與狀態同步的全流程閉環。
4. **單座原子化** — 單座建築物失敗不中斷整體迴圈，確保流水線韌性。
5. **品質閘門** — GitHub Actions 流水線於 `main` 分支執行 CodeQL 與 SonarQube 掃描，要求零重大漏洞後方可部署。
6. **可觀測性** — CrewAI 透過 `step_callback` 與 `task_callback` 捕捉中間思考，寫入 `intermediate_research.json` 供狀態檢視與條件判斷。
7. **文檔完整** — 產出完整文檔集並以 mdBook 發佈靜態網站，README 連結至所有必要文件。
8. **版本治理** — 所有變更遵循分支流動 `dev-001 → dev → main`，CHANGELOG 遵從語意化版本號。

## 專案約束

- **技術強制約束** — 必須採用 CrewAI 作為多代理框架，嚴禁以自定義手寫 Agent 取代；Crew 以 Python 腳本形式由 n8n 的 `Execute Command` 節點呼叫執行。
- **觸發器分離** — n8n 僅透過 Webhook 或外部系統觸發啟動；Cron 排程屬於 GitHub Actions（`0 9 * * *`，HKT 17:00），不在 n8n 中設定。
- **分支流動固定** — 每座建築物的提交推送至 `dev-001`，GHA 流水線自動依序合併至 `dev` 再至 `main`；嚴禁直接推送至 `dev` 或 `main`。
- **提交訊息規範** — 提示詞工作流提交標題為 `feat(scaffolding): {簡述}`；每座建築物提交標題為 `feat(building): add biography and tour guide for {中文名稱}`，並附 body。
- **版本號規範** — CHANGELOG 遵從語意化版本號，每座建築物或每輪提示詞工作流追加一筆紀錄並依變更級別調升版號。
- **基礎設施** — n8n 為自架 Docker 容器（永久免費 Community Edition），綁定 `0.0.0.0:45678` 對外暴露；Webhook 觸發器需要可達的主機。
- **授權** — 專案採用 MIT 授權條款。
- **語言** — 所有文檔與導賞手冊內容以繁體中文撰寫，建築物名稱保留中文名稱。
- **單一 CI/CD 檔案** — GitHub Actions 僅有單一統合檔案 `gh-pipeline.yml`，不允許新增其他 workflow 檔案。
- **原子化提交** — 每座建築物獨立提交，僅 stage 該建築物產出，確保可追溯與可回滾。

## 章程修訂
